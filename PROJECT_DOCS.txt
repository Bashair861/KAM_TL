IMPORTANT TYPE NOTE:
  accounts.id is TEXT (values like "starlight", "axiom", not UUIDs).

  This affects: account_history.account_id (TEXT).
  All other FKs (stakeholders, health_scores, etc.) also use TEXT for account_id.

5. ROW LEVEL SECURITY (RLS)
────────────────────────────────────────────────────────────────────────────────
RLS is ENABLED on all tables.
Read policies:  public SELECT (anon + authenticated can read all rows)
Write policies: authenticated UPDATE on accounts, health_scores, health_metrics
                authenticated INSERT on account_history

How to enable RLS + add read policies:
  Run src/db/enable-rls.sql in Supabase SQL Editor.

Write policies are added by the migration scripts:
  add-kam-assignment.sql              → UPDATE policy on accounts
  add-kpi-data.sql                    → UPDATE policies on health_scores + health_metrics
  add-account-history.sql             → SELECT + INSERT policies on account_history
  add-account-insert-policy.sql       → INSERT policy on accounts
  add-health-scores-insert-policy.sql → INSERT policy on health_scores

Without read policies: anon key returns 0 rows (blocked by RLS).
Without RLS at all: Supabase shows critical security warning in dashboard.

7. DATA SERVICE LAYER (src/services/db.js)
────────────────────────────────────────────────────────────────────────────────
All Supabase queries and mutations are centralised here.
Components never call supabase directly.

READ functions:

  fetchAccounts(opts?)
    → Returns FlatAccount[] filtered by role/userId
    → opts: { role, userId } — KAM role filters by assigned_kam_id
    → Used on: dashboard, accounts list, contracts, strategy pages

  fetchAccount(id)
    → Returns full Account shape (all nested data) or null
    → Uses Promise.all for 7 parallel queries
    → Used via TanStack Router loader in accounts.$accountId.jsx

  fetchContracts(opts?)
    → Returns ContractRow[] — accounts joined with contract_details
    → Adds: duration, autoRenew, nonTerminator, priceHike fields
    → Role filtering same as fetchAccounts
    → Used on: contracts page

  fetchKamUsers()
    → Returns KAM-role profiles only (for assignment dropdown)
    → Excludes Head of KAM — can only assign to KAMs

  fetchEscalations(accountId?)
    → Returns Escalation[] with nested escalation_action_items
    → Used on: escalations page + account detail Escalation tab

  fetchOpportunities(accountId?)
    → Returns Opportunity[]
    → Used on: account detail Activity tab

  fetchNotifications()
    → Returns Notification[]
    → Not yet wired to sidebar (sidebar still uses static mock data)

  fetchAccountHistory(accountId)
    → Returns HistoryEntry[] ordered by edited_at DESC
    → Used on: account detail Client History tab

WRITE functions:

  updateAccountKam(accountId, kamId)
    → Updates accounts.assigned_kam_id

  updateAccountKyc(accountId, updates)
    → Updates KYC columns on accounts table
    → fields: industry, business_info, client_history, revenue, mrr_arr,
              primary_contact_name, engagement_tenure, team_size,
              competitors (array), main_business_flow

  updateHealthBlock(accountId, area, score, metricUpdates, kpiData)
    → UPSERTS health_scores: INSERTs if no row exists, UPDATEs if one does
    → Uses maybeSingle() — never throws on missing rows (handles new accounts)
    → Updates each health_metrics row by UUID (skipped if metricUpdates is empty)
    → area values: 'relationship' | 'project' | 'white_space' | 'csat' | 'risk' | 'financial'

  createAccount(data)
    → INSERTs a new row into accounts table
    → Required fields: id (slug), name, shortCode, industry, region, tier,
      contractType, contractValue, arr, renewalDays
    → Optional: primaryContactName, assignedKamId
    → Auto-set defaults: health=50, trend=0, status='healthy', retention_risk='Low',
      growth_upside=0, white_space_count=0, is_startup=false, last_touch='Just now'
    → Requires INSERT RLS policy (add-account-insert-policy.sql)

  logAccountChanges(accountId, changes[], editedBy)
    → Inserts rows into account_history
    → changes: Array<{ field: string, oldValue: string, newValue: string }>
    → editedBy: profile display name (e.g. "Julian Drake")
    → Called alongside every write operation in the same mutationFn

Mapper functions:
  mapFlatAccount()  — snake_case DB row → camelCase FlatAccount object
  mapHealthBlock()  — health_scores + health_metrics rows → HealthBlock shape
  block() helper in fetchAccount — when health_metrics is empty but kpi_data exists,
    derives metric bars from KPI sections (score = checked weight ÷ total × 10).
    Derived metrics have id "derived-N" — display only, not updatable by UUID.

8. AUTHENTICATION (src/context/AuthContext.jsx + src/services/auth.js)
────────────────────────────────────────────────────────────────────────────────
Auth provider:  Supabase Auth (email + password)
Auth method:    supabase.auth.signInWithPassword({ email, password })

AuthContext provides:
  session  → Supabase session object (null if logged out)
  profile  → Row from profiles table { id, name, initials, role, email }
  loading  → true until first getSession() resolves

Profile loading (loadProfile):
  1. Try: SELECT * FROM profiles WHERE id = <auth user UUID>
  2. If not found: SELECT * FROM profiles WHERE email = <auth email>
  Fallback handles mismatch between seeded static UUIDs and real auth UUIDs.

Route protection (AppShell in __root.jsx):
  - Unauthenticated + not on /login → navigate('/login')
  - Authenticated + on /login → navigate('/')
  - While loading → full-screen spinner

Sign out:
  AppSidebar → LogOut button → signOut() → supabase.auth.signOut()
  → AuthContext onAuthStateChange clears session + profile

Account detail uses TanStack Router async loader:
  loader: async ({ params }) => {
    const account = await fetchAccount(params.accountId);
    if (!account) throw notFound();
    return { account };
  }
  Component: Route.useLoaderData() → { account }
  useRouter().invalidate() re-runs the loader after a KPI save

All other pages use useQuery() for client-side fetching.
